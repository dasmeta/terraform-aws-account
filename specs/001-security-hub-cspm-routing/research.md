# Research decisions

1. **Existing wrapper**: Keep `dasmeta/monitoring/aws//modules/security-hub` as the Security Hub provider wrapper. The account module already groups Config, Inspector, GuardDuty, Macie, aggregation, and notification inputs. No new upstream collection is needed because this extends an existing module.
2. **Corrective start boundary**: Use an existing approved Standard Step Functions state machine and an EventBridge role with only `states:StartExecution` on its exact ARN. A state machine execution role must separately restrict resource-changing actions. [AWS EventBridge target roles](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-events-iam-roles.html).
3. **Finding scope**: Match `RecordState=ACTIVE`, `Workflow.Status=NEW|NOTIFIED`, `Compliance.Status=FAILED`, `Compliance.SecurityControlId` exact values, `AwsAccountId` current account, and `Resources.Id` exact values. The workflow rechecks the chosen resource because an EventBridge array match does not identify which element matched. [AWS finding patterns](https://docs.aws.amazon.com/securityhub/latest/userguide/securityhub-cwe-all-findings.html), [array matching](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-event-patterns-arrays.html).
4. **Failure layers**: A target SQS DLQ records inability to start a workflow. Standard Step Functions failure events and AWS/States metrics record failures after successful start. Evidence must include execution history and post-action validation; configuration is design evidence only. [AWS EventBridge DLQ](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-rule-dlq.html), [Step Functions events](https://docs.aws.amazon.com/step-functions/latest/dg/eventbridge-integration.html).
5. **No automatic remediation default**: The map defaults empty. The name, owner, runbook, exact resource IDs, and exact workflow ARN are mandatory per enabled entry; `*` is rejected. Approvals remain operational and outside Terraform.
6. **Repetition**: Security Hub publishes updates as new events. The workflow must tolerate duplicate or repeated triggers and perform post-action checks before declaring success.
